The agent loop — one turn, step by step

The model cannot act. It reads context, proposes an action, the harness checks and executes it, and the result re-enters the context. Press play or step. At the approval gate, the choice is yours.

The red dashed edge exists so side effects are impossible without you. Read-only actions auto-approve in the AI4REDS configuration; anything that writes, deletes, or sends data outside must be approved. Deny it and the model re-plans — the loop handles both paths.

The context window — the model’s memory, and it fills up

Everything the model sees is tokens: the persona, the conversation, every tool result. Add work and watch the bar fill. Fill it — the compression model takes over. Or keep big results out with a sub-agent.

Illustrative token counts; real sizes depend on the model and the vLLM configuration. The harness re-sends the whole context on every turn — that is why skill bodies load only when triggered, sub-agents keep big results in their own context, and old turns can be compressed. Every token you save is latency and cost you save on every turn.

Simulator rule: 2+ keyword hits ≈ the agent recognizing its trigger. The real mechanism: the agent reads every description and decides — so the description must say when the skill applies, written for the agent, not for a human. helpful scores 1 keyword on the proposal task and is close-but-no: one keyword is not a trigger. That is exactly why “A skill for proposals” never fires.

SOUL.md — the persona: changes everything, costs every conversation

Same model, same context, same question. Only the persona file differs.

You: “Ernesto, the ECG monitor test failed — can you look?”

The agent reads every line of SOUL.md in every conversation — each line costs context. Keep only rules that must hold at all times; task-specific workflows belong in skills.
