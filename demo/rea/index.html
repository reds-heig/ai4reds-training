One MCP server + CLI that gives your AI agent superpowers for reverse engineering: see a feature you like, and understand how it works — down to the binary level. No source code required.

1 · What it is

Reverse engineering, plugged into your AI agent

REA connects a coding agent (Claude Code, Codex, Cursor, Gemini CLI, and many others) to a toolbox for inspecting software without its source code — native binaries, JavaScript & Electron apps, .NET assemblies, websites, Android APKs, network captures, databases and dozens more formats. You ask a question about an app’s feature; the agent investigates the real file and comes back with an answer, plus the evidence (code, references, strings) and the known limitations of each conclusion.

Agent-first, but a real CLI

Same investigation workflows over MCP (for agents) and the terminal. npx rea-agents setup registers it with your agent; rea … works standalone.

Many targets, one interface

Native binaries, JS/Electron, .NET, APKs, websites, HAR/pcap captures, SQLite, Go, Rust, WASM, ML model files, firmware, PyInstaller, Godot, IL2CPP… one consistent toolset.

Evidence, not vibes

Findings ship with the supporting code, symbols and references — and explicit statements of what could not be determined. Useful output you can verify.

2 · How it works

The investigation loop

REA is not a standalone decompiler — it orchestrates analysis for your agent.

The loop, adapted from the REA repo's own figure (website/public/assets/figures/rea-investigation-flow.svg).

You ask

“How does search work in the Notes app? Show me the evidence.”

Agent calls REA

Your agent invokes REA tools over MCP — or you run the equivalent CLI command yourself.

REA inspects & traces

Local analysis: built-in static parsers (JS, .NET, ELF, PE, APK, …) and, for deep native decompilation, your Hopper, Ghidra or IDA installation. REA starts engines as needed.

Findings + evidence back

Pseudocode, modules, calls, strings, references — with limitations noted. The agent explains, then can implement and test a similar feature in your project.

Local & auditable: analysis runs on your machine against local targets — REA does not upload your apps. (Your agent’s own model provider has its own data policy.)
3 · What you can analyze

From executables to websites

The headline categories — the repo lists 36 target types in total. built-in means no extra decompiler or engine required.

Native binaries

Pseudocode, assembly, strings, symbols, calls and references from compiled executables (ELF, PE, Mach-O, DOS 16-bit…).

needs Hopper, Ghidra or IDA

JavaScript / Electron apps

Modules, imports, source maps, routes, IPC boundaries and native add-on relationships — from an extracted app directory, or the ASAR archive (the packed form of an Electron app).

built-in · Node + npm

.NET assemblies

Metadata, bytecode (CIL) instructions, declared native dependencies and build comparisons. Static only — the app never runs.

built-in · static

Android APKs & devices

Manifest, classes, decompiled methods, signatures (v1–v3.1); plus live devices over adb (packages, logs, dumps, screen capture).

headless JADX + JDK · adb

Websites & networks

Page structure, scripts and screenshots via a Chrome-family browser; HAR / SAZ / pcap captures decoded into requests, responses and source locations.

Chrome-family browser · tshark for pcap

The long tail

Go & Rust binaries, WASM, EVM bytecode, ML models (GGUF/safetensors), IL2CPP, Godot PCK, firmware, PyInstaller, GPU code objects, SQLite databases, Apple crash reports, kernel modules…

mostly built-in static
4 · Use it yourself

Three ways in

① Into your AI agent (recommended)

Prerequisite: Node.js 22/24/26 + npm. Setup registers REA’s MCP server and workflow instructions with your agent (with backups), then you restart the agent.

# one command — pick your agent, review & approve changes
$ npx rea-agents setup
you → your agent
“Understand how search works in the Notes app, show me the evidence, and build a similar feature for my project.”

② From the terminal

Same workflows, no agent needed. Handy for scripting and for quick static analysis of a JS/Electron app folder or ASAR:

# one-off
$ npx -y rea-agents@latest analyze-javascript-application /absolute/path/to/app --json

# or install the `rea` command permanently
$ npm install --global rea-agents
$ rea --help
# REA changes fast — keep it fresh
$ rea update
Native decompilers: deep binary analysis uses your Hopper, Ghidra or IDA — you must be legally licensed for any commercial tool. Setup can optionally install Hopper (with your approval). Static JavaScript and .NET analysis need no native engine at all.

6 · Good to know

Fine print, in one glance

Lawful use only

REA is for research, education, interoperability, software preservation, and analyzing software you own or are authorized to examine.

Bring your own decompiler license

IDA Pro, Hopper and JEB are commercial. REA grants no license, key or activation — use legally obtained copies.

Trust but verify

Results include explicit limitations; decompilation is reconstruction, not ground truth. Verify conclusions against the evidence before relying on them.
